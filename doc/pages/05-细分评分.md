# 多项细分评分页面规划（已确认，已实现）

## 页面原则

- 不改变现有品牌色、卡片、按钮和大屏视觉体系。
- 评分项是工作表单，不做花哨图表；评委首先看清选手、评分项、当前总分和是否完成。
- 专家 iPad 横屏优先，大众手机竖屏同步适配。
- 整体评分保持现有页面；只有启用细分评分的群体进入新表单。

## B7 轮次管理：评分规则配置

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ☑ 专家评审       评分制       群体权重 [50] %       满分 [100]       │
├──────────────────────────────────────────────────────────────────────┤
│ 评分方式   ( ) 整体评分     (•) 细分评分                              │
│                                                                      │
│ 计分模式   ( ) 分值分配：各项满分合计100，得分直接相加                │
│            (•) 百分制加权：各项均按100分评价，再按比例合成100          │
│                                                                      │
│ 评分项                    满分              比例              操作   │
│ ① 第一道菜               100 分            [50] %            删除   │
│ ② 第二道菜               100 分            [50] %            删除   │
│ ＋ 添加评分项                                  合计：100% ✓           │
│                                                                      │
│ 试算验收   第一项 [97]   第二项 [99]   →   合成总分 98.00 / 100       │
│                                                                      │
│ 最终折算   评委合成总分 → 多人平均 → × 专家评审群体权重50%            │
└──────────────────────────────────────────────────────────────────────┘
```

### 配置交互

- 选择“分值分配”时，列为“评分项、满分、顺序”，底部校验满分合计。
- 选择“百分制加权”时，满分固定显示 100，只编辑名称和比例，底部校验比例合计。
- 试算输入只用于验证规则，不写入任何选手成绩。
- 群体权重继续放在群体卡片顶部，评分项比例放在评分项表内，视觉上明确是两层概念。
- 有成绩后整个评分规则区域显示锁定说明，不允许通过浏览器禁用绕过。
- 保存失败保留当前编辑内容，不使用浏览器原生 `alert/confirm/prompt`。

### 手机竖屏调整

- 左侧选手列表改为顶部横向选手编号条，当前选手高亮。
- 评分项纵向排列，输入框和加减按钮保持足够触控面积。
- 合成总分固定在评分项末尾；底部提交栏不遮挡最后一项。

### 逐人填写 / 多人同页

- 选项只在细分评分表单显示；整体评分继续沿用现有全部选手列表。
- `逐人填写`：使用上述“选手导航 + 当前选手表单”，适合评分项较多或需要逐个核对。
- `多人同页`：一次展开当前批次的全部选手卡片，每张卡片包含全部评分项和该选手合成总分；不再显示左侧逐人导航。
- 多人同页只渲染当前批次，不把其他批次选手混入长页面。顶部保留“已评 / 未完整 / 未评分”统计和当前批次锚点。
- 两种视图共用同一份评分状态，切换时不调用提交 API、不清空输入、不生成新的评分记录。
- 视图偏好按评委 token 保存在当前设备，刷新和下一批次继续使用；其他评委和其他设备不受影响。
- 默认使用逐人填写，评委可主动切换。多人同页下点击统计或未完成选手时，页面滚动并高亮对应卡片；逐人填写下则切换到对应选手。
- 提交前确认、未完整校验、本地暂存和提交后锁定在两种视图中完全一致。

### 填写与提交

- 评分项初始为空白，不用默认 0 冒充已填写；评委明确输入 0 才视为已评 0 分。
- 一位选手只要填写过任意项，就必须补齐该项选手的全部评分项。
- 完全未触碰的选手沿用当前“未评分按 0 分计”确认规则，并在最终确认框逐位列出。
- 切换选手不提交网络请求；整个批次仍一次提交，成功后锁定。
- 未提交内容暂存在当前设备；页面刷新后提示可恢复。批次、群体或 token 不一致时不得恢复。
- 提交前展示每位选手的合成总分及未完整项，禁止只显示一个笼统总数。
- 已提交页可查看本人逐项分数，但不可修改。

## B11 成绩页：选手评分明细

```text
01号 张师傅                         轮次总分 86.40
专家评审  平均 98.00/100  权重50%  折算49.00

  评分项汇总
  第一道菜   平均97.20/100   比例50%   平均贡献48.60
  第二道菜   平均98.80/100   比例50%   平均贡献49.40

  逐评委明细
  评委A   第一道菜97→48.50   第二道菜99→49.50   总分98.00   个人折算9.80
  评委B   第一道菜96→48.00   第二道菜98→49.00   总分97.00   个人折算9.70
  ...
```

- 默认先显示群体平均分与折算，评分项和逐评委明细按需展开，避免主成绩表过长。
- 分值分配模式不显示比例列，逐项贡献等于该项原始得分。
- 整体评分只显示总分，不伪造“评分项”。
- 评分项平均分仅用于分析；正式群体平均分仍从每位评委合成总分计算。

## 我的评分记录

- 按轮次列出本人每个评分项原始分、比例、逐项贡献和合成总分。
- 显示提交时间、批次、当前是否已被后台重置。
- 不显示其他评委姓名或分数。

## 异常与空状态

- 未配置评分项：细分评分不能保存，提示“至少添加 2 个评分项”。
- 比例或满分错误：在合计处和具体行同时提示。
- 待开始且已有成绩：说明先清空测试数据后修改；轮次已开始：说明评分规则已锁定，暂停也不能修改，需要新规则时新建轮次。
- 本地暂存与服务端规则不一致：不恢复旧表单，提示联系管理员确认规则。
- 网络失败：保留当前填写内容，允许重试，不重复提交。
- 无成绩：成绩页只显示空状态，不显示 0 分逐项明细。
