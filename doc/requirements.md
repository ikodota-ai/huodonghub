# 需求文档

## 产品形态

系统 = **两个独立功能模块**，无贯穿层级（2026-09-17 决策，废弃早期"活动贯穿"方案）：

- **视频分组**：新建分组 → 传视频 → 生成链接/二维码 → 发给客户。一个分组 = 一个对外链接 `/v/{code}`
- **投票评选**：新建投票 → 配轮次/群体/选手/评审 → 现场使用 → 结果导出。多届活动 = 每届新建一次投票，历史归档可查

两模块各自管理、各自生成对外链接与二维码，互不强关联。

## F1 视频分组展示（刚需 1）

- 后台：本地上传 MP4（大文件分片），按分组管理；分组可"开放/暂停"（暂停后客户页显示未开放，不输出任何视频地址，防止空耗带宽）；单视频可单独下架
- 上传后流水线：ffmpeg 转 H.264 + faststart（边下边播）、自动截封面、记录时长/大小
- 视频文件随机路径存放（`/media/{随机串}/xxx.mp4`），Nginx 直接分发，支持拖动播放
- 客户页：移动优先，按分组链接 + 自动生成二维码访问；微信内打开体验良好
- 压制规范：1080p 码率 2~4Mbps（依服务器带宽再调）

## F1.5 链接导入工具

- 后台粘贴**公众号文章链接**（mp.weixin.qq.com），解析文中视频 → 选清晰度 → 下载 → 走同一套流水线入分组
- 元数据记录来源链接与导入时间，便于溯源
- 定位：历史视频抢救工具，best-effort 维护（微信改页面结构时可能失效，失败给明确提示转人工）
- **视频号链接不做自动化提取**，实测不可行，结论见 `research-wechat-video.md`
- **视频抢救工作台**（后台页面）：把人工抢救流程做成系统内的标准动作——内置两条人工通道的操作指引（下载助手公众号 / PC 微信+下载工具），抢救到的 MP4 在此上传，走同一套 ffmpeg 流水线入分组；source 标记 rescue，可记录原视频号链接便于溯源
- **不做服务器端微信协议机器人**（"下载助手"的自建版），理由见 `research-wechat-video.md`

## F2 投票评分（刚需 2）

结构：**投票** → **轮次** → 选手。一次投票可开多轮（初赛/复赛/决赛/加时），选手库挂在投票下，每轮勾选本轮参赛名单（支持晋级淘汰）。

**多群体权重计分**（对齐部门在用的参考系统，素材验算见 `pages/00-页面地图.md`）：

- 每轮以**勾选卡片**启用群体，三个预设（专家评审/大众评审/观众评审）+ 可加自定义群体，权重可视化校验合计=100%：
  - 专家评审（评分制，默认 60%）：限定名单，礼仪小姐持 iPad 扫码进入打分（0~满分），选手群体得分 = 评委平均分
  - 大众评审（评分或投票可选，默认 20%）：**扫码绑定微信**（首次扫码静默绑定 openid/指纹，转发无效，详见 pages/00），得分同评分制或按投票制
  - 观众评审（投票制，默认 20%）：大屏扫码开放进入，每人限 N 票，得分 = 得票 ÷ 参与人数 × 100（归一）；可选"固定分值"模式（1票=N分）
- 每群体设权重%，轮内合计 100%；**轮次总分** = Σ（群体得分 × 权重）
- **跨轮聚合**：聚合结果页多轮总分相加排名，逐群体明细，可导出（参考 `references/成都分赛区聚合结果.pdf`）

**现场页面**：

- 观众投票 H5（扫码进入，倒计时，剩余票数，投票即时反馈）
- 评委评分页（iPad，大字大按钮，提交锁定，打分/投票两种形态）
- 大屏页（二维码模式 + 图表模式，SSE 实时，键盘控制：Q/2 显隐二维码、←→切群体、R 显隐数值、F 全屏；参与率、权重、最后更新时间与参考系统一致）
- 大屏控制台（后台远程控制大屏：切群体/显隐结果/显隐二维码/倒计时/开关投票）

**后台管理**：届次/轮次（群体配置动态行+权重校验）/选手（CSV 批量导入）/评委（口令二维码+打印视图）/结果（单轮+聚合+CSV 导出+逐评委审计明细）。

**并发设计**：投票接口 = 一次 INSERT + 计数器 UPDATE；大屏读冗余计数字段，不扫明细表；现场"开始投票"峰值几百上千并发可承受。

**限票与身份**：每次投票独立配置微信服务号（AppID/AppSecret，不同投票可用不同公众号，2026-09-17 用户确认）。已配置 → 网页授权拿 openid，一人一票最严谨，大众评审绑定也用 openid；未配置 → 设备指纹 + IP 降级方案。

## F3 AI 能力（远期，先占位）

- 第一阶段：AI 工具导航 + SOP 板块（PPT 制作、AI 图片、声音复刻、对口型、数字人口播分别对应什么工具、怎么操作），零成本
- 第二阶段：API 集成，服务商可插拔（DeepSeek / 火山引擎 / RunningHub / LibLib），API Key 后台可配
- 候选能力：PPT 生成（LLM 大纲 + 模板渲染）、文案/口播稿（LLM）、AI 图片（按张计费）、声音复刻、对口型、数字人短视频

## 非功能需求

- 客户侧页面移动优先，微信内打开为主战场
- 带宽保护：分组开关 + 随机媒体路径；未来必要时升级 Nginx X-Accel 鉴权
- 服务器是借的：存储层必须可切换（本地盘 → OSS/VOD 只改配置），数据定期备份到本地

## 明确不做

- 不用 RuoYi / Java / PHP（决策理由见 architecture.md）
- 不用 Docker
- 不做视频号自动化提取
- 不做服务器端微信协议机器人（模拟登录微信的 bot）
- 不做公开注册，后台账号由管理员创建
