# 草稿期清分与历史活动细分评分设计

## 背景与决策

历史活动可以使用整体评分、分值分配或百分制加权，但评分规则与成绩必须按轮次生命周期保护。用户已确认采用 A 方案：观众投票群体可单独清空测试票，所有清分操作仅允许在轮次 `pending`（待开始）执行；`active`、`paused`、`finished` 均不允许清分。

这里的“草稿期”指轮次待开始，不以活动顶部的 `vote.status` 代替。暂停只是现场控制状态，不会重新开放清分权限。

## 历史活动规则

- 待开始且无评分数据：可直接修改评分模式、评分项、满分和比例。
- 待开始且已有测试评分：先清空本轮测试数据，再修改评分规则。
- 已开始、已暂停或已结束：评分规则锁定，原有评分与投票结果保留；需要新规则时新建轮次。
- 迁移前已存在的历史群体仍默认 `single`，不自动转换历史成绩。

## 观众测试票清空

在轮次配置的观众投票群体卡片中提供“清空测试票”，仅 `pending` 显示；无票时禁用并显示当前票数。

清空范围仅当前群体：

- 删除该群体 `vote_entries`。
- 删除该群体 `group_stats` 缓存，由后续结果查询按零票展示。
- 若属于限定名单投票，重置该群体评审的 `hasVoted/votedAt`，保留人员、二维码和设备绑定。
- 保留群体配置、选手、其他群体评分与投票。

前端显示不可恢复确认框；服务端重新校验群体类型、归属和轮次状态，成功后发布大屏更新事件。

## 统一清分防线

- 控制台“清空本轮数据”改为仅 `pending` 可用，删除原先“暂停后可清空”的绕行路径。
- 评委完整重置仅 `pending` 可用，会清除本人成绩与提交状态。
- 正式开始后评委操作改为“解除绑定”：只清 `boundKey/boundAt`，保留成绩、投票和提交状态，支持现场换设备。
- 正式开始后禁止删除仍有关联评分或投票的评委，避免通过删除人员级联清分。
- 删除群体或轮次时，如会删除正式成绩，同样拒绝。
- 所有限制以服务端为最终防线，按钮隐藏或禁用只用于体验，不能替代接口校验。

## 接口与界面

- 新增群体测试票清空接口，仅接受 `kind=vote` 且所属轮次为 `pending`。
- 评委重置接口显式区分完整重置和仅解除绑定，避免调用方误清成绩。
- 评分编辑器根据“已有成绩”或“轮次已开始”显示不同锁定原因。
- 控制台在非待开始状态禁用整轮清空，并说明“正式开始后不可清分”。

## 验收

1. 历史待开始活动无成绩时可切换细分评分；有测试成绩时须先清空。
2. 待开始观众群体可单独清空测试票，其他群体数据与评委绑定不变，大屏立即刷新。
3. `active/paused/finished` 的整轮清空、群体清空和完整评委重置均返回 409，数据库无变化。
4. 正式开始后解除绑定成功，成绩、票数与提交状态不变。
5. 正式开始后不能通过删除评委、群体或轮次清除已有结果。
6. 整体评分、观众正常投票、大屏和既有细分评分回归不受影响。
