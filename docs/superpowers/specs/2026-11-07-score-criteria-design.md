# 多项细分评分设计（已确认，未实施）

## 1. 背景与决策

现有评分群体只保存一位评委对一位选手的一个总分。新需求要求专家评审、大众评审均可独立启用多项评分，同时保留整体评分活动。

采用结构化评分项方案：新增评分项配置与逐项成绩，现有 `score_entries.score` 继续保存每位评委合成后的百分制总分，`group_stats` 仍保存总分合计。大屏、群体均分、群体权重、跨轮聚合沿用现有口径。

不采用“一个菜品拆成一个评审群体”，也不采用只存 JSON 的明细方案。

## 2. 目标与非目标

### 目标

- 每个 `kind=score` 的评审群体独立配置整体评分或细分评分。
- 专家评审、大众评审均支持分值分配、百分制加权两种细分模式。
- 服务端生成单个评委的百分制总分，再计算选手平均分与群体折算分。
- 后台可核对每项原始分、比例、逐项贡献、个人总分、平均分与最终折算。
- 历史活动、观众投票、大屏和现有成绩单保持兼容。

### 非目标

- 不给观众投票增加评分项。
- 不为同一群体的不同选手配置不同评分项。
- 不在大屏展示逐项柱状图，大屏仍展示群体结果与总分。
- 不在已有成绩后提供评分规则版本切换；必须先清空该群体成绩。
- 不改变现有输入精度：首版逐项输入沿用整数评分，合成、平均和折算结果保留两位小数。

## 3. 两种权重与三种评分模式

### 两层权重

1. **评分项比例**：把一个评委的多项评分合成为 100 分制总分。
2. **评审群体权重**：把多位评委的总分取平均后，折算进选手最终成绩。

两者必须分开配置、分开命名、分开验算，禁止共用一个 `weight` 字段。

### 模式定义

| `scoreMode` | 中文名称 | 配置约束 | 单个评委总分 |
| --- | --- | --- | --- |
| `single` | 整体评分 | 无评分项，直接输入 0~maxScore | 沿用现有输入 |
| `sum` | 分值分配 | 各项满分合计等于群体 maxScore | `Σ 各项得分` |
| `weighted` | 百分制加权 | 每项固定满分 100，各项比例合计 100% | `Σ（各项得分 × 比例）` |

启用 `sum` 或 `weighted` 时，群体 `maxScore` 固定为 100；只有整体评分允许沿用其他满分，避免其他满分与百分制加权混用。

### 必过算例

分值分配：两道菜各 50 分，得分为 47、46，则总分 `47+46=93.00`。

百分制加权：两道菜各 50%，得分为 97、99，则总分 `97×50%+99×50%=98.00`。

百分制加权：主菜 60%、副菜 40%，得分为 97、99，则总分 `97×60%+99×40%=97.80`。

若上述百分制加权结果属于专家群体，且专家群体权重为 50%，选手专家平均分为 98，则专家群体折算为 `98×50%=49.00`。若有 5 位评委，某评委个人总分 98 的折算贡献为 `98÷5×50%=9.80`，5 人贡献合计仍为 49.00（实际以各人分数计算）。

## 4. 配置生命周期

- 仅 `kind=score` 显示评分模式；`kind=vote` 不显示、不保存评分项。
- 整体评分不保存评分项。从细分切回整体时必须没有成绩，并明确提示将移除未使用的评分项配置。
- 分值分配模式保存各项名称、满分、排序，比例字段为空。
- 百分制加权模式保存各项名称、比例、排序，满分固定为 100。
- 每项名称必填且同一群体内不可重复；首版每项群体至少 2 项、最多 10 项。
- 新建轮次复制上一轮时，同时复制评分模式和评分项，并生成全新 ID，禁止沿用上一轮评分项 ID。
- 群体存在任意 `score_entries` 后，满分、评分模式、评分项名称、满分、比例、排序全部锁定。清空该群体成绩并重建计数器后才允许修改。
- 删除轮次、群体、评委成绩或清空轮次时，逐项明细随总评分记录一起清理。

## 5. 数据模型规划

### `vote_groups` 新增

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `score_mode` | varchar(16)，默认 `single` | `single / sum / weighted` |

### 新增 `score_criteria`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | bigint PK | 评分项 ID |
| `group_id` | bigint FK | 所属评分群体 |
| `name` | varchar(64) | 第一道菜、口味、技法等 |
| `max_score` | decimal(5,2) | 分值分配的各项满分；加权模式固定 100 |
| `weight` | decimal(5,2)，可空 | 百分制加权比例；分值分配为空 |
| `sort` | int | 展示顺序 |

索引：`group_id + sort`；同一群体评分项名称唯一。

### 新增 `score_item_entries`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | bigint PK | 明细 ID |
| `score_entry_id` | bigint FK | 关联现有总评分记录 |
| `criterion_id` | bigint FK | 关联评分项 |
| `score` | decimal(5,2) | 该项原始得分 |
| `created_at` | datetime | 提交时间 |

唯一约束：`score_entry_id + criterion_id`。删除总评分记录时级联删除逐项明细；删除整个群体或轮次时同步级联。

### 保留现有结构

- `score_entries.score`：服务端合成后的单个评委总分。
- `group_stats.value_cache`：各评委总分之和，不直接累加逐项分。
- 参评人数仍按 `score_entries` 的评委数统计，不能按逐项明细行数统计。
- 重建计数器仍从 `score_entries.score` 汇总；逐项明细用于审计与展示，不参与第二次累计。

## 6. 提交与计算规则

### 评委 GET

整体评分响应保持现有结构。细分评分额外返回 `scoreMode`、`criteria` 和已提交逐项成绩；未提交时不返回其他人的任何分数。

### 评委 POST

整体评分沿用现有 `scores` 结构。细分评分每位选手提交：

```json
{
  "contestantId": "选手ID",
  "items": [
    { "criterionId": "评分项ID", "score": 97 },
    { "criterionId": "另一评分项ID", "score": 99 }
  ]
}
```

浏览器可以同时显示总分，但服务端不信任浏览器提交的总分。

### 服务端校验

- 评分项必须全部属于当前群体，ID 不可重复，不允许缺失或额外项。
- 逐项分数不得小于 0、不得超过该项满分；首版必须为整数。
- 当前选手必须属于本轮和当前批次，评委不得重复提交。
- 分值分配在保存配置时校验满分合计；百分制加权在保存配置时校验比例合计。
- 提交时在事务中写入总评分、逐项明细并更新群体计数器，任一步失败全部回滚。

### 计算与舍入

- 先计算每位评委的合成总分并保留两位小数，再以该总分计算选手平均分和群体折算。
- 分值分配总分为各项原始得分之和。
- 百分制加权总分为各项原始得分乘比例之和，最后统一四舍五入到两位小数。
- 页面展示的逐项贡献可保留两位小数，但不能把各项展示值四舍五入后再拼成总分。
- 多个评委的参评人数、缺席、批次和 `avgMode` 继续沿用现有规则。
- 未来若实现“去掉最高分、最低分”，去除对象是评委的合成总分，不是单个评分项。

## 7. 页面设计

页面线框和交互详见 `doc/pages/05-细分评分.md`。

- 后台群体卡片：评分模式、评分项编辑、合计校验、规则说明和实时试算。
- 评委评分页：整体评分保持现状；细分评分采用“选手导航 + 当前选手逐项表单 + 自动总分 + 整批提交”。
- 评委端细分评分提供“逐人填写 / 多人同页”视图选项；选择仅保存在当前评委、当前设备，不进入计分规则，不影响其他评委。
- 成绩明细：先展示选手群体汇总，再展开评分项汇总和逐评委逐项明细。
- 我的评分记录：只读展示本人逐项得分、逐项贡献和合成总分。
- 大屏：不改变页面结构和计分显示。

## 8. 导出

现有主结果 CSV 保持原有列与口径。新增“逐项评分明细 CSV”，至少包含：

`活动、轮次、选手编号、选手姓名、评审群体、群体权重、评分模式、评委、评分项、该项满分、该项比例、该项原始分、该项贡献、评委合成总分、参评人数、选手群体平均分、群体折算分`。

投票群体不输出评分项行；整体评分可输出一行“整体评分”，评分项比例为空。

## 9. 权限与兼容

- 评分项配置、成绩查看和导出沿用投票归属及维护人员权限。
- 评委只能查看自己的逐项评分记录。
- 历史群体迁移后默认 `single`，历史 `score_entries` 不需要补逐项明细。
- 整体评分提交、评委二维码绑定、分批切换、清票、重计、聚合和 SSE 行为不得改变。
- MySQL 5.7，仅使用普通表、索引、外键和事务，不使用窗口函数、CTE 或 CHECK。

## 10. 验收清单

1. 历史整体评分活动无需配置即可继续评分，结果与升级前一致。
2. 专家与大众可分别选择不同评分模式和不同评分项。
3. 47+46 的分值分配总分为 93；97、99 各 50% 的合成总分为 98；60%/40% 时为 97.80。
4. 评分项满分或比例不等于要求时不能保存，并明确定位错误项。
5. 合成总分、个人折算、群体平均分、群体折算和轮次总分满足算例。
6. 事务中断后不出现只有总分没有明细、只有部分评分项或计数器重复的数据。
7. 评分提交后配置锁定；清空成绩后才可修改，重新提交不会沿用旧评分项 ID。
8. 删除、重置、清空和重建后人数、总分、逐项明细及计数器一致。
9. 分批评分切换时不串选手、不串批次、不误判已提交。
10. 逐人填写与多人同页共用评分状态，切换视图不丢分、不提交、不重复计数；再次进入记住该评委在当前设备上的视图选择。
11. 成绩页、我的记录、逐项 CSV 与数据库原始分及总分一致。
12. 大屏和跨轮聚合在相同总分下与升级前结果一致。
13. 观众投票页面、限票和计分逻辑完全不受影响。
