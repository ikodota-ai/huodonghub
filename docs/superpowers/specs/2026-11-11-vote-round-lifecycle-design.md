# 投票活动与轮次两层状态设计

## 背景

当前系统同时存在投票活动状态和轮次状态，但两者都展示“进行中”，且清空权限只按轮次 `pending` 判断。实际现场需要先以活动彩排状态产生测试数据、清空测试数据，再转为正式活动；按轮次是否待开始判断清空权限无法覆盖这一流程。

## 目标

- 活动状态负责数据安全，轮次状态负责现场提交节奏。
- 彩排时可以正常评分、投票并清空；正式后任何清空入口都不能通过暂停或删除关联记录绕过。
- 转为正式前必须没有进行中轮次，且整个活动不存在评分或投票流水，防止彩排数据混入正式结果。
- 不改变计分、投票配额、批次、评委绑定及大屏统计口径，不新增数据库字段或状态枚举。

## 状态模型

内部枚举保持不变，仅调整管理界面的中文语义。

| 层级 | 内部值 | 界面名称 | 职责 |
| --- | --- | --- | --- |
| 活动 | `draft` | 彩排 | 允许彩排提交、清空数据及现有规则编辑 |
| 活动 | `active` | 正式 | 正式成绩保护，禁止清空 |
| 活动 | `finished` | 已结束 | 全活动只读，禁止提交和清空 |
| 活动 | `archived` | 已归档 | 全活动只读，禁止提交和清空 |
| 轮次 | `pending` | 待开始 | 禁止本轮提交 |
| 轮次 | `active` | 进行中 | 活动为彩排或正式时允许本轮提交 |
| 轮次 | `paused` | 暂停 | 禁止本轮提交，保留数据 |
| 轮次 | `finished` | 已结束 | 禁止本轮提交，保留结果 |

活动为彩排或正式时，提交权限完全由轮次状态及原有观众时间窗决定。活动为已结束或已归档时，即使轮次仍为进行中，观众、专家和大众评委也不能继续提交；大屏、结果页和历史记录仍可查看。

## 活动转换

普通设置不再提供可任意前后跳转的状态下拉框，改为明确的生命周期操作：

1. 彩排 → 正式：按钮“转为正式”。
2. 正式 → 已结束：按钮“结束活动”。
3. 已结束 → 已归档：按钮“归档活动”。

普通管理界面和接口均不允许正式退回彩排、已结束退回正式或跨级跳转。需要重新彩排时复制活动或新建活动，不提供常规解锁入口。

转为正式必须同时满足：

- 当前没有 `active` 状态的轮次，避免转换期间继续写入彩排数据。
- 整个活动的 `score_entries` 和 `vote_entries` 均为 0；否则返回 409，并报告评分、投票条数，提示先逐轮清空彩排数据。

检查与状态更新在同一事务中执行。正式、已结束和已归档活动均保持原有数据，不做迁移或自动清零。

## 清空边界

控制台按钮改名为“清空彩排数据”，仅活动为彩排时可用，不再按轮次是否待开始决定。彩排活动中，轮次为待开始、进行中、暂停或已结束均可清空；界面建议先暂停，避免清空期间继续写入。

该操作沿用当前整轮清空语义：

- 删除当前轮次所有专家、大众评委评分及级联细分评分明细。
- 删除当前轮次所有观众投票流水和所有批次统计。
- 删除群体统计缓存，重置评委提交状态和提交时间。
- 保留活动、轮次、选手、批次、群体、权重、评分规则、评委名单、二维码口令及设备/微信绑定。
- 保持当前轮次状态不变，并发布大屏更新。

以下入口统一按活动状态判断，避免绕过：

- 控制台整轮清空。
- 投票群体单独清空。
- 单个评委完整重置。
- 删除带有评分或投票的评委、群体、轮次等关联记录。

活动不是彩排时，上述清空和带数据删除均返回 409。单个评委“解除绑定”仍可在正式后使用，只清设备关系，保留成绩、投票和提交状态。评分规则编辑仍沿用原来的轮次 `pending` 与成绩保护条件，不因活动为彩排而额外放开已开始轮次的规则编辑。

## 界面调整

- 活动状态统一显示“彩排 / 正式 / 已结束 / 已归档”。
- 轮次控制按钮使用“开始本轮 / 暂停本轮 / 结束本轮”，避免与活动状态混淆。
- 清空按钮使用“清空彩排数据”，危险确认文案明确会清除全部评分和投票、保留配置与绑定且不可恢复。
- 正式活动的清空按钮禁用并说明原因；评委列表继续提供“解除绑定”。
- 活动已结束或已归档时，观众和评委页面显示活动已结束，不再显示可提交界面。

## 兼容与性能

- 无数据库迁移，现有活动内部状态值和全部业务数据不变。
- 现有生产 `active` 活动直接视为正式活动，清空入口自动受保护。
- 观众 POST 在现有轮次上下文中同时读取活动状态，评委查询复用已有关系，不增加高频数据库往返。
- 活动转换和清空均为低频管理操作，不改变投票高峰事务、计分或 SSE 写票路径。

## 验收场景

1. 彩排活动 + 进行中轮次：专家和观众可提交；暂停后可整轮清空，配置与绑定保留，大屏归零。
2. 彩排活动 + 暂停/已结束轮次：整轮清空、投票群体清空和单个评委完整重置均允许。
3. 有进行中轮次时转为正式：返回 409，状态不变。
4. 有评分或投票时转为正式：返回 409 并显示条数，状态和数据不变。
5. 无进行中轮次且无流水时转为正式：成功；之后暂停轮次也不能清空，所有绕过入口均返回 409。
6. 正式活动的单个评委可解除绑定，评分、投票和提交状态保持不变。
7. 正式退回彩排、已结束退回正式及跨级转换均被接口拒绝。
8. 已结束/已归档活动即使轮次为进行中，专家和观众提交仍被拒绝，历史结果可查看。
9. 原有评分规则编辑权限、批次配额、限票、计分和大屏统计回归不变。
10. 浏览器完成“彩排提交 → 暂停 → 清空 → 转为正式 → 开始本轮 → 正式提交 → 清空被拒”的完整流程。

## 非目标

- 不增加专家、大众、观众各自独立的开始/暂停开关。
- 不提供正式活动解锁、退回彩排或清分入口。
- 不改变结束本轮后现有结果展示和跨轮聚合规则。
- 不通过放宽限流、异步票账或新增缓存改变投票性能口径。
